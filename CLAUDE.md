# Working in this repo

- Every change goes through a `feature/<name>` branch and a pull request to `main`, merged once the `test` check passes. Follow the `feature-branch` skill before the first edit.
- Merging to `main` deploys staging automatically. Production is deployed by hand (`deploy` skill); never start it unless asked.
- `node scripts/check-sizes.mjs && node scripts/check-structure.mjs && npx nx run-many -t lint test && npx nx run everise:build --configuration=production && npx nx run everise:build --configuration=staging` must exit 0 before pushing (the same as the `test` check). The build matters: the specs don't type-check templates.
- Follow the `frontend-best-practices` skill for any TypeScript, component, store or library change: where code goes (feature, widget, data-access, ui, util; one component per folder, stores and services only in data-access), stores for state, no `any`, API types in `@everise/core/api-types`, `serverMessage()` for errors, and the size limits (a component class over 200 lines gets split).
- The site looks like Final Fantasy XIV. Only the theme is global: `libs/ui/components/src/theme` (tokens, reset, element typography, layout grid, text helpers), loaded by `apps/everise/src/styles.scss` and nothing else. Every component styles itself in its own `.scss` next to its `.ts`, with role tokens: the UI building blocks in `libs/ui/components/src/<block>/` (each with its spec), and pages, navbar and footer in their own folders. Features reuse the building blocks (`cdtButton`, `cdtInput`, `<cdt-field>`, `<cdt-checkbox>`, `<cdt-switch>`, `<cdt-tooltip>`, `<cdt-panel>`, `<cdt-card>`, `<cdt-banner>`, `<cdt-dialog>`, `<cdt-byline>`, `cdtTabs`/`cdtTab`, `cdtTag`, `<cdt-pager>`, `<cdt-icon>`, `<cdt-avatar>`, `<cdt-message>`, `<cdt-turnstile>`); a new kind of control goes into the UI library first. Follow the `theme` skill before touching any template or style.
- The frontend must stay WCAG 2.2 AA compliant in both colour modes. Follow the `accessibility` skill for every template, style, route or component change, and check with it before pushing.
- Deployed builds call the relative `/api`, which `worker/index.ts` forwards to the environment's backend Worker (`../typescript-cloudflare-backend`) over the service binding in `wrangler.jsonc`. `environment.ts` is the local dev build, calls a backend directly, and is meant to be edited by hand. See the `deploy` skill.
